R36S Hacking

  • Updated November 2026: this page is now about Linux 7.3, U-Boot v2026.10 and Buildroot 2026.08.

The R36S is a hand-held game console that you can buy online.
This page is about how to use the R36S as a Linux platform for your own software. To use it as a game console, use ArkOS or one of the other custom firmware systems.
It has the following basic hardware:

  • RK3326 processor
    • Quad-core ARM Cortex-A35 CPU (64-bit)
    • Mali-G31 GPU
    • Up to 1.5 GHz. This software runs the CPU at a maximum of 1.3 GHz.
    • Datasheet
  • 1GB DDR3L
  • 640*480 3.5-inch LCD
  • 3200 mAh Battery (Replaceable) (JST connector)
  • Built in mono speaker
  • 2x TF/microSD Slot
  • 2x USB-C connectors (1x data, 1x charge)
  • Dual analog joysticks, direction pad and 10 additional buttons

The R36S is very similar to the ODroid Go Super. Or the ANBERNIC RG351V

Software

Mainline Linux and U-Boot do not support the R36S, but they support its RK3326. These branches add the R36S:

  • Linux 7.3: github.com/AndreRenaud/linux-r36s (branch r36s-v7.3)
  • U-Boot v2026.10: github.com/AndreRenaud/u-boot-r36s (branch r36s-v2026.10)
  • Buildroot 2026.08.1: github.com/AndreRenaud/buildroot-r36s (branch r36s-2026.08)

Buildroot gets Linux and U-Boot from GitHub at fixed commits. It builds the full SD card image from source. The image starts the Quake II demo (Yamagi Quake II, OpenGL ES 3) at boot.

These parts operate correctly:

  • The LCD, with a boot logo
  • The GPU (Mesa Panfrost, OpenGL ES 3)
  • Sound through the speaker (RK817 codec)
  • All buttons and the two analog sticks, as one gamepad
  • USB Ethernet on the USB-C data port, in U-Boot and Linux
  • The battery, CPU frequency scaling and temperature sensors
  • Reboot
Build Instructions These instructions are for a Debian or Ubuntu machine on x86_64. Other Linux distributions need similar packages. 
# Install the necessary tools on your Linux machine
sudo apt update && sudo apt install build-essential git bc cpio unzip rsync file wget python3

git clone -b r36s-2026.08 https://github.com/AndreRenaud/buildroot-r36s.git
cd buildroot-r36s
make r36s_defconfig
make
The last command downloads and builds all the software. On an AMD Ryzen 9 7950X3D (16 cores), this takes approximately 45 minutes. The result is output/images/sdcard.img (1.6 GB). Write it to an SD card of 2 GB or larger: 
sudo dd if=output/images/sdcard.img of=/dev/sdX bs=4M conv=fsync

Caution: replace /dev/sdX with the device of your SD card. Make sure that it is the correct device. The command erases all data on it.

Note: the build downloads the id Software Quake II demo data. This data is not free software. Its licence allows only non-commercial use, and it does not allow public display. The image includes the licence, in /usr/share/games/quake2/demo-license.txt. To build without the data, disable BR2_PACKAGE_YQUAKE2_DEMO_DATA (make menuconfig).

Using the Image
  • Serial console: connect a 3.3 V serial adapter to the UART pads (see the photo). Use 1500000 baud, 8N1.
  • Log in as root. The password is root.
  • Ethernet does not start automatically. To start it, type ip link set eth0 up && udhcpc -i eth0. Then you can connect with SSH.
  • To set the volume, type amixer sset Master 175 (range 0 to 255). 175 is comfortable on the speaker.
  • To stop Quake II, type /etc/init.d/S12userapp stop.
  • To try a new kernel, copy Image and rk3326-r36s.dtb to /boot, then reboot.
  • To get the U-Boot prompt, push Ctrl-C many times on the serial console while the R36S starts.

Network boot

U-Boot can load the kernel and device tree from a TFTP server. The root filesystem stays on the SD card. The ASIX AX88772B adapter is tested. U-Boot also has drivers for AX88179, RTL8152 and SMSC95xx adapters.

  1. Connect the Ethernet adapter to the USB-C data port.
  2. Copy output/images/image.itb to your TFTP server, as r36s/image.itb.
  3. On the R36S, type these commands: 
    fw_setenv tftpserver 192.168.1.10
fw_setenv netboot 1
reboot
    Use the IP address of your TFTP server. The network must also have a DHCP server.

If the network boot fails, U-Boot boots from the SD card. To stop the network boot, type fw_setenv netboot.

SD Card Layout

The RK3326 has no on-board flash. Its boot ROM loads U-Boot from the SD card, then U-Boot loads Linux.

Offset Length Description
0 512B Master boot record
32kB ~9MiB U-Boot
10MiB 510MiB FAT filesystem, mounted on /boot: Image, rk3326-r36s.dtb, uboot.env and image.itb
520MiB 1GiB ext4 root filesystem (read-write)

U-Boot boots Image and rk3326-r36s.dtb. If this fails, it boots image.itb (the same kernel and device tree, in one file). The U-Boot environment is the file uboot.env. To read or change it from Linux, use fw_printenv and fw_setenv.

Boot Time

Times after a reboot, from the reset (reboot: Restarting system):

Event Time
U-Boot starts the kernel 1.0 s
Quake II starts 3.2 s
The first level is loaded 11.3 s

These changes make the boot fast:

  • U-Boot starts the data cache before it relocates itself. It starts the LCD panel while it reads the kernel from the SD card.
  • U-Boot reads the SD card in DDR50 mode, and loads the kernel without a FIT image.
  • The kernel configuration is small. The drivers for the boot are built in, so no modules load at boot.
  • Before Quake II starts, udev sets up only the input, DRM and sound devices. The other devices continue in the background.

Writing Your Own Application

The script /etc/init.d/S12userapp starts Quake II as the user player. To start your application, change this script (in Buildroot: board/r36s/overlay/etc/init.d/S12userapp).

Use SDL with the KMS/DRM video driver and OpenGL ES. The image has SDL2 and SDL3. For an example in Go, see r36s-demo-app. It is in the image, but it does not start at boot.

The buttons and the two analog sticks are one input device, "R36S Gamepad" (the r36s-gamepad daemon). SDL3 maps it as a standard gamepad, so use the SDL gamepad API:

Boot To Ebitengine

An Ebitengine game can draw directly on the LCD, without X11 or Wayland. Ebitengine uses EGL, OpenGL ES and GBM/KMS for this (Ebitengine v2.11, at this time the main branch). It loads these libraries when the game starts.

  1. Build the game with Go for linux/arm64. Put it in the root filesystem, for example with a Buildroot package.
  2. Start the game from S12userapp as the user player. This user can use the display, sound and input devices.

Ebitengine uses "R36S Gamepad" as a standard gamepad. Sound plays through ALSA.

Times from the reset, for the Flappy Gopher example:

Event Time
U-Boot starts the kernel 1.0 s
The game starts 3.2 s
The first frame shows 5.6 s

On the first boot after you write the SD card, the first frame shows at 7.2 s. Mesa must then compile its shaders. It keeps them for the subsequent boots.
